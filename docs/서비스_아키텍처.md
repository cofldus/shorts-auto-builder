# 서비스 아키텍처

## 목표

- 키워드 입력만으로 `script.txt` 자동 생성
- 사용자 첨부 편집과 생성형(무에서 유) 렌더를 모두 지원
- 음성 모드 선택(`none`, `edge`, `piper`, `openai`)

## 구성

- 프론트엔드: `apps/web` (Next.js, Vercel 배포)
- API 게이트웨이: `apps/web/app/api/*`
  - `/api/script`: 스크립트 생성
  - `/api/jobs`: 첨부 편집 워커 호출
  - `/api/creative`: 생성형 워커 호출
- 렌더링 워커: `worker/main.py`
  - `/render-upload`: 첨부 파일 기반 편집
  - `/generate-creative`: 키워드 기반 생성형 렌더
  - `/generate-creative-upload`: 생성형 + 소스 미디어 업로드 렌더
  - `/generate-creative-async`: 생성형 비동기 큐 등록
  - `/generate-creative-upload-async`: 업로드 포함 생성형 비동기 큐 등록

## 생성형 모드

- `mock`: 로컬 합성 자산으로 비용 없이 테스트
- `openai_image`: 이미지 생성 API 기반 장면 생성
- `external_video`: 외부 영상 생성 provider API 기반 장면 생성
- `replicate_video`: Replicate 전용 어댑터 기반 영상 생성
- `runway`: Runway 기반 영상 생성
  - `text_to_video`: 텍스트 프롬프트 기반
  - `image_to_video`: 이미지 + 프롬프트 기반
  - `video_to_video`: 비디오 + 프롬프트 기반

## 저장소 출력

- `STORAGE_BACKEND=local`: 로컬 파일 경로 반환
- `STORAGE_BACKEND=s3`: S3/R2 업로드 후 `output_url` 반환
- `S3_URL_MODE=presigned`: presigned URL 반환

## 상태 조회

- 워커: `GET /jobs/{job_id}`
- 웹: `GET /api/jobs/{jobId}`
- 흐름: `queued -> processing -> completed/failed`

## 배포 메모

- Vercel 함수는 오케스트레이션만 담당
- 실제 렌더링/업로드는 별도 워커에서 수행
- 운영 시 Redis 큐 + 상태 저장소 추가 권장
