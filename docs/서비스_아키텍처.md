# 서비스 아키텍처

## 목표

- 키워드 입력만으로 `script.txt` 자동 생성
- 사용자 첨부 편집과 생성형(무에서 유) 렌더를 모두 지원
- 음성 모드 선택(`none`, `edge`, `piper`, `openai`)

## 구성

- 프론트엔드: `apps/web` (Next.js, Vercel 배포)
- API 게이트웨이: `apps/web/app/api/*`
  - `/api/script`: 스크립트 생성
  - `/api/jobs`: 첨부 편집 워커 호출
  - `/api/creative`: 생성형 워커 호출
- 렌더링 워커: `worker/main.py`
  - `/render-upload`: 첨부 파일 기반 편집
  - `/generate-creative`: 키워드 기반 생성형 렌더

## 처리 흐름

1. 사용자가 주제/톤/길이를 입력
2. 스크립트 생성 또는 즉시 생성형 렌더 실행
3. API 게이트웨이가 워커로 전달
4. 워커가 자산 준비 후 `python -m shorts_maker` 실행
5. 결과 MP4 경로를 응답으로 반환

## 생성형 모드

- `mock`: 로컬에서 장면 자산을 생성해 비용 없이 테스트
- `openai_image`: 장면 이미지를 API로 생성해 보다 자연스러운 결과

## 배포 메모

- Vercel 함수는 오케스트레이션(요청/상태)만 담당
- 실제 렌더링은 별도 워커(Cloud Run/Render/Railway) 분리
- 장기적으로는 S3/R2 저장소 + 작업 큐(예: Redis) 결합 권장
